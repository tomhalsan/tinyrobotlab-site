Lab note 01 / Issue #9 · Review in PR #103

A source inherited another candidate's raw score

What happened?

While I was building Tiny Agent Lab's Issue #9 source-quality evaluator, an independent architecture review of the initial implementation found a ranking bug. A stale loop variable in the final ranking phase could cause a retained source to inherit another candidate's provider-relevance raw_score.

Why did the tests miss it?

The PR history records the review finding and the targeted regression tests added afterward, but does not identify a more specific gap in the earlier tests. The new test gives two candidates different raw scores, evaluates them in both input orders, and compares their resulting ranks.

What changed?

The evaluator now keeps raw scores by URL and looks up the score belonging to each item during ranking. The regression test makes order invariance explicit:

What I learned

Passing tests and review are both evidence, not proof. Here, review surfaced an interaction the earlier tests had not pinned down. The regression test narrows that gap; it does not prove the evaluator correct for every input.

Architectural guardrails I use

These are practices I can point to in the current Tiny Agent Lab codebase.

  1. Keep boundaries replaceable

    The Research Agent defines ResearchExecutor and InferenceProvider ports separately from their implementations. Tests cover executor selection and provider substitution.

  2. Treat scores as evidence, not truth

    The Issue #9 evaluator records quality signals and ranking rationale. PR #103 frames these as ranking aids, not proof of factual truth.

  3. Test order-sensitive assumptions

    The Issue #9 regression test reverses candidate order with different provider scores and asserts that the ranked results remain unchanged.
